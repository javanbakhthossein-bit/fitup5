 فیتاپ — ترمیم اضطراری دیتابیس سرور (fitup-db-repair) — ۲۶ سپتامبر
════════════════════════════════════════════════════════════════

■ مشکل شما
  در بیلد نسخهٔ ۱۴۰ این خطا تکرار شد و بعدش سایت بالا نمی‌آید و
  دیتابیس هم ندارد:

    [HeadCodeInjector] DB error: PrismaClientUnknownRequestError
    ConnectorError { SqliteError { extended_code: 11,
    message: "database disk image is malformed" } }

■ معنی خطا
  کد و بیلد سالم‌اند — این خطا یعنی فایل db/custom.db روی سرور
  «خراب/Corrupt» شده (معمولاً به‌خاطر خاموشی ناگهانی سرور، پر شدن
  دیسک، یا kill -9 وسط نوشتن). هیچ ورژنی از کد این را حل نمی‌کند؛
  فایل دیتابیس باید ترمیم شود.

■ راه‌حل — ۳ قدم (۲ دقیقه)
  1) این فایل را آپلود کنید کنار package.json روی سرور و باز کنید:
       unzip fitup-db-repair-2026-09-26.zip -d .
     (اسکریپت: scripts/prod-db-repair-v141.mjs — یا فایل mjs را
      مستقیم در ریشهٔ پروژه بگذارید)

  2) سرور را موقتاً خاموش کنید:
       pm2 stop fitup        (یا روش همیشگی خودتان)

  3) اجرا:
       node prod-db-repair-v141.mjs
     (اول می‌خواهید فقط ببینید:  node prod-db-repair-v141.mjs --dry-run)

■ اسکریپت چه می‌کند؟ (کاملاً امن)
   ✓ تشخیص دقیق خرابی (integrity_check)
   ✓ قبل از هر کاری بکاپ کامل فایل خراب در پوشهٔ corrupt-backup-<زمان>
   ✓ ریکاوری ۳ لایه:
       ۱. کپی ساختاری پایتون (اگر فایل قابل‌خواندن باشد)
       ۲. نجات رکوردبه‌رکورد با عبور از صفحات خراب
       ۳. sqlite3 رسمی .recover (اگر نصب باشد)
   ✓ راستی‌آزمایی: فقط فایلی که integrity_check آن «ok» باشد قبول می‌شود
   ✓ تعویض اتمی + فعال‌سازی مجدد WAL
   ✓ گزارش شمارش جداول (چند کاربر/پرداخت نجات یافت)

■ بعد از ترمیم
   pm2 restart fitup
   curl -I http://localhost:3000   → باید 200 بدهد

■ اگر «کاربران = 0» بود
   یعنی صفحاتِ حاوی کاربران خراب شده‌اند. آن‌وقت:
   - بانک حرکات/غذاها را با این دو بسته برگردانید (در download/ هم هست):
       fitup-exercise-sync-2026-09-24.zip   (۵۸۱ حرکت)
       fitup-food-sync-2026-09-24.zip       (۵۰۰ غذای جدید)
   - کاربران دوباره ثبت‌نام می‌کنند؛ پرداخت‌های اخیر را با پنل
     زرین‌پال/کافه‌بازار تطبیق دهید.

■ جلوگیری از تکرار (خیلی مهم)
   1) بکاپ خودکار روزانه — این خط را در crontab -e بگذارید:
        10 4 * * * cd /path/to/project && mkdir -p db/backups && sqlite3 db/custom.db ".backup db/backups/daily-$(date +\%a).db"
   2) دیسک را خالی نگه دارید:  df -h   (اگر بالای ۹۰٪ بود پاک کنید)
   3) هرگز سرور را kill -9 نکنید؛ pm2 stop/reload استفاده کنید.

■ تست انجام‌شده
   اسکریپت روی دیتابیس عمداً خراب‌شده (همان الگوی خطای شما) تست شد:
   پرداخت‌ها ۵۰/۵۰ و کاربران ۱۵۹/۲۰۰ نجات یافت؛ فایل نهایی ۱۰۰٪ سالم.
