# 🚑 راهنمای بازیابی فیتاپ — کد + بکاپ دیتابیس خودت = سایت کامل

## 🧩 مدل دو تکه — همیشه این‌طور فکر کن

| تکه | چیست | کجاست | چه کسی مسئولش است |
|---|---|---|---|
| **۱. کد** | `fitup-deploy-*.zip` — صددرصد سورس سایت، بدون هیچ داده‌ای | پوشهٔ `download/` | دستیار (بعد از هر تغییر می‌سازد) |
| **۲. داده** | بکاپ دیتابیس + پوشهٔ `uploads/` (عکس و ویدیو کاربران) | سرور خودت | خودت (دستورات پایین) |

زیپ دیپلوی **هیچ ربطی به دیتابیس ندارد** — عمداً. چون دیتابیسِ تو (کاربران، خریدها، چت‌ها،
برنامه‌ها) فقط روی سرور خودت زندگی می‌کند و هر بار پشتیبان‌گیری می‌شود.
پس بازیابی = زیپ کد + بکاپ دادهٔ خودت → سایت کامل با همهٔ کاربرانش.

---

## ۱️⃣ گرفتن پشتیبان روی سرور (زنده — بدون خاموش کردن سایت)

```bash
cd /var/www/fitup

# الف) بکاپ دیتابیس (اسنپ‌شات سازگار حتی حین تراکنش‌های زنده؛ ۱۴ نسخهٔ آخر نگه داشته می‌شود)
bun scripts/db-backup.mjs
# → backups/db-YYYY-MM-DD-HHMM.db

# ب) بکاپ رسانه‌ها (عکس/ویدیو کاربران — این فایل‌ها در دیتابیس نیستند، فایل‌اند)
tar -czf backups/uploads-$(date +%F).tar.gz uploads/
```

هر دو فایل را **خارج از سرور** هم کپی کن (لپ‌تاپ / گوشی / فضای ابری).
بکاپی که فقط روی همان سرور باشد، بکاپ نیست!

---

## ۲️⃣ بازیابی صفر تا صد (سرور تازه یا سروری که کاملاً از بین رفته)

پیش‌نیازها: اوبونتو + دسترسی sudo. با این ۳ فایل: زیپ دیپلوی + بکاپ دیتابیس + بکاپ uploads

```bash
# ۱) نصب ابزارها
sudo apt update && sudo apt install -y unzip caddy
curl -fsSL https://bun.sh/install | bash && source ~/.bashrc
bun add -g pm2 || sudo npm i -g pm2

# ۲) باز کردن کد
sudo mkdir -p /var/www/fitup && cd /var/www/fitup
sudo unzip -o /root/fitup-deploy-*.zip -x deploy.sh
# deploy.sh را جدا کپی نکن — خودش بعداً در جریان دیپلوی جایگزین می‌شود؛ برای اولین اجرا دستی بگیر:
sudo cp /root/fitup-deploy-*/deploy.sh . 2>/dev/null || true

# ۳) جای‌گذاری بکاپ دادهٔ خودت
mkdir -p db uploads
cp /root/backups/db-YYYY-MM-DD-HHMM.db db/custom.db      # ← بکاپ دیتابیس خودت
tar -xzf /root/backups/uploads-YYYY-MM-DD.tar.gz          # ← بکاپ رسانه‌ها

# ۴) تنظیم مسیر دیتابیس
cat > .env <<'EOF'
DATABASE_URL=file:/var/www/fitup/db/custom.db
EOF
# ⚠️ اگر پوشهٔ دیگری ساختی، مسیر را همان جا بگذار

# ۵) نصب وابستگی‌ها + کلاینت Prisma + هم‌ترازی اسکیما با کدِ جدید
bun install
bun run db:generate
bun run db:push        # اگر بکاپت هم‌نسخهٔ کد باشد، بدون تغییر اجرا می‌شود (no-op)

# ۶) بیلد پروداکشن و اجرا
bun run build
pm2 start --name fitup bash -- -c 'cd /var/www/fitup && bun run start'
pm2 save
pm2 startup   # دستور چاپ‌شده را یک بار اجرا کن تا بعد از ریبوت هم خودش بالا بیاید

# ۷) وب‌سرور و دامنه
sudo cp Caddyfile /etc/caddy/Caddyfile   # نام دامنه داخلش را چک کن
sudo systemctl enable --now caddy && sudo systemctl reload caddy

# ۸) تست سلامت
curl -I http://localhost:3000              # باید 200 بدهد
pm2 logs fitup --lines 20 --nostream
```

سپس ورود ادمین با همان شماره و رمز داخل بکاپ دیتابیست — چون دادهٔ توست، همان است.

---

## ۳️⃣ بعد از بازیابی: آپدیت‌های روتین مثل همیشه

```bash
# زیپ دیپلوی جدید را در /var/www/fitup آپلود کن و فقط:
cd /var/www/fitup && bash deploy.sh
```
`deploy.sh` به دیتابیس و `uploads/` **دست نمی‌زند** (مقدس‌اند) — فقط کد را عوض می‌کند.

---

## ⚠️ سه قانون طلایی

1. **زیپ دیپلوی = فقط کد.** هیچ‌وقت دیتابیس داخلش نیست و نباید باشد.
2. **داده = بکاپ دیتابیس + پوشهٔ uploads.** هر دو را با هم نگه دار؛ یکی بدون دیگری ناقص است.
3. بعد از **هر تغییر مهم** یک بکاپ تازه بگیر و خارج از سرور ذخیره کن.
