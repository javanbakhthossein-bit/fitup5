## این نسخه در یک نگاه — چه چیزی عوض شد؟

**مشکلی که گزارش کردی:** از هر ۳-۴ بار بستن و باز کردن اپ، بعد از ویدیو یک صفحهٔ «اتصال اینترنت برقرار نیست» می‌آمد و بعد خودش وارد داشبورد می‌شد. و قبل از ویدیو هم یک لحظه صفحهٔ مشکی دیده می‌شد.

**ریشه‌ای که پیدا کردم:**
- وقتی اپ را باز می‌کنی، گاهی اینترنتِ گوشی هنوز کامل وصل نشده (مخصوصاً دیتای موبایل بعد از بستن اپ). اپ قبلاً همان لحظه لود می‌زد، شکست می‌خورد و به‌جای صبر، صفحهٔ «در حال اتصال/اتصال برقرار نیست» را نشان می‌داد — بعد از چند ثانیه خودش وصل می‌شد و می‌رفت داشبورد. یعنی **یک مدال الکی بود، نه قطعی واقعی**.
- صفحهٔ مشکی هم به این دلیل بود که پشت ویدیو رنگ مشکی گذاشته شده بود و مدت کوتاهی (تا آماده شدن ویدیو) دیده می‌شد.

**چه کردم:**
1. **آن صفحه دیگر وجود ندارد** — نه در ظاهر، نه در کد. حالا اگر اینترنت دیر وصل شود، همان اسپلش/ویدیوی خود فیتاپ روی صفحه می‌ماند و اپ در پس‌زمینه خودش بی‌صدا تلاش می‌کند؛ به‌محض آماده شدن، مستقیم داشبورد می‌آیی.
2. **اپ حالا باهوش شده:** موقع باز شدن اول اینترنت را چک می‌کند؛ اگر هنوز وصل نشده، صبر می‌کند تا وصل شود (حداکثر ۶ ثانیه) و بعد لود می‌زند — یعنی حتی فرصتِ به‌وجودآمدن خطا هم از بین رفته.
3. **مشکی قبل از ویدیو صفر شد:** همهٔ رنگ‌های پشت ویدیو الان «عین اولین فریم ویدیو» نارنجی است + یک پوستر از خود فریم اول ویدیو زیر ویدیو نشسته — از لحظهٔ اول فقط شروع ویدیو را می‌بینی. نوارهای نارنجی بالا/پایین مثل قبل سر جایشان هستند.
4. **ضریب اطمینان اضافه (سمت سایت):** اگر یک لحظه خطای شبکه در خود سایت رخ دهد، در اپ‌ها فقط اسپلش برند نشان داده می‌شود و خودش ترمیم می‌کند — هیچ کارت خطایی هرگز در اپ دیده نمی‌شود.
5. محتوای داخلی هر دو اپ (تصاویر/فونت‌ها/فایل‌های سایت) به آخرین نسخهٔ سایت تازه شد.

## گام ۱ — دیپلوی (کپی/پیست یک‌جا)

1. فایل `fitup-deploy-2026-10-08-v224.zip` را روی سرور آپلود کن (مثلاً به `/root`).
2. **کل بلاک زیر را یک‌جا کپی کن، در ترمینال سرور پیست کن و اینتر بزن:**

```bash
bash <<'FITUP_DEPLOY_224'
# ═══════════════════════════════════════════════════════════
#  فیتاپ v224 — دیپلوی (unzip + ری‌استارت)
#  مطمئن: پوشهٔ db و uploads و .env دست‌نخورده می‌مانند
# ═══════════════════════════════════════════════════════════
set -e
APP_DIR="/var/www/fitup"
ZIP="/root/fitup-deploy-2026-10-08-v224.zip"

echo "── ۱) پشتیبان سریع از دیتابیس ──"
DBF=$(ls -t "$APP_DIR"/db/*.db 2>/dev/null | head -1 || true)
if [ -n "$DBF" ]; then
  cp "$DBF" "/root/fitup-db-backup-$(date +%Y%m%d-%H%M%S).db" && echo "   ✅ بکاپ دیتابیس در /root ذخیره شد"
fi

echo "── ۲) unzip زیپ v224 ──"
cd "$APP_DIR"
unzip -oq "$ZIP" -d /tmp/fitup-v224
# همه‌چیز جز db و uploads و .env و .next/cache از روی پوشهٔ استخراج‌شده کپی می‌شود
rsync -a --exclude 'db/' --exclude 'uploads/' --exclude '.env' --exclude '.next/cache/' /tmp/fitup-v224/ "$APP_DIR"/
rm -rf /tmp/fitup-v224
echo "   ✅ فایل‌های v224 جایگزین شدند"

echo "── ۳) نصب وابستگی (فقط اگر package.json عوض شده باشد) ──"
cd "$APP_DIR"
if ! cmp -s package.json /tmp/fitup-last-package.json 2>/dev/null; then
  npm install --omit=dev --no-audit --no-fund 2>&1 | tail -1 || echo "   (npm install رد شد — عادی است)"
fi
cp package.json /tmp/fitup-last-package.json

echo "── ۴) ری‌استارت سرویس ──"
(pm2 restart fitup || pm2 restart all) 2>&1 | tail -2
sleep 4
pm2 status | grep -E "fitup|name" || true
echo "   ✅ v224 بالا آمد"
FITUP_DEPLOY_224
```

3. اگر npm install از قبل اجرا شده باشد، چند ثانیه بیشتر طول نمی‌کشد.

## سؤال‌های احتمالی

**«پس چرا قبلاً این صفحه می‌آمد؟»** — چون اپ قبل از چک‌کردن اینترنت، مستقیم لود می‌زد و موقع شکست، صفحهٔ پیام می‌ساخت. حالا هم صبرِ هوشمند داریم هم هیچ صفحهٔ خطایی در کد وجود ندارد که نشان داده شود.

**«اگر اینترنت واقعاً قطع باشد چه؟»** — اپ روی اسپلش خودش می‌ماند (لوگو + اسپینر) و هرچند ثانیه بی‌صدا دوباره تلاش می‌کند. تا اینترنت بیاید، وارد داشبورد می‌شوی. هیچ پیام خطا، هیچ دکمهٔ اضافه.

**«آیا چیزی از امکانات قبلی کم شده؟»** — نه. ورود، پنل، پرداخت، کیف پول، اعلان‌های Firebase، حالت باشگاه — همه دقیقاً مثل قبل. این نسخه فقط «شروعِ اپ» را تمیز کرد.
