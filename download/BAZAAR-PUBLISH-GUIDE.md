## فاز ۳ — تنظیم پرداخت درون‌برنامه‌ای (مهم‌ترین فاز)

> ⚠️ طبق قانون انتشار بازار: کالای دیجیتال/اشتراک (مانند پلن‌های تناسب اندام)
> **باید** از پرداخت درون‌برنامه‌ای بازار فروخته شوند — نه درگاه مستقیم.

### ۳.۱ — ساخت محصولات (کالای مصرفی — Consumable)

در پیشخان → برنامه فیتاپ → تب **«پرداخت درون‌برنامه‌ای»**:

برای هر پلن یک **کالا (Product — مصرفی/Consumable)** بسازید:

| شناسه محصول (SKU) | نوع | عنوان فارسی | قیمت (تومان) |
|---|---|---|---|
| `fitup_basic` | کالا (مصرفی) | فیتاپ اقتصادی — ۴۵ روز | ۳۵۰,۰۰۰ |
| `fitup_standard` | کالا (مصرفی) | فیتاپ استاندارد — ۴۵ روز | ۸۰۰,۰۰۰ |
| `fitup_advanced` | کالا (مصرفی) | فیتاپ پیشرفته — ۴۵ روز | ۱,۲۰۰,۰۰۰ |
| `fitup_ultimate` | کالا (مصرفی) | فیتاپ حرفه‌ای — ۴۵ روز | ۱,۸۰۰,۰۰۰ |

> چرا کالا و نه اشتراک (Subscription)؟
> - دوره‌های مجاز اشتراک بازار فقط ۱/۷/۳۰/۶۰/۹۰/۱۸۰/۳۶۵ روز است — پلن ۴۵ روزه‌ی فیتاپ در هیچ‌کدام نمی‌گنجد.
> - کالای مصرفی دقیقاً همان مدل زرین‌پال سایت است: کاربر پلن می‌خرد، ۴۵ روز استفاده می‌کند، برای تمدید دوباره می‌خرد.
> - اپ بعد از فعال‌سازی موفق روی سرور، خرید را **consume** می‌کند تا خرید مجدد (تمدید) ممکن باشد.

> نکته: قیمت‌ها را با قیمت‌های سایت هماهنگ نگه دارید (قیمت نهایی هر پلن در بازار ملاک است).
> ⚠️ SKUها دقیقاً همین نام‌ها باشند — کد اپ با فرمت `fitup_{planId}` آن‌ها را صدا می‌زند.

### ۳.۲ — کپی کلید RSA ✅ (انجام شده)

همان تب «پرداخت درون‌برنامه‌ای» → **کلید عمومی RSA** را کپی کنید.

این کلید باید در `fitup-bazaar/app/build.gradle.kts` قرار گیرد:

```kotlin
buildConfigField("String", "BAZAAR_RSA_PUBLIC_KEY", "\"MIIBIjANBgkq...کلید شما...\"")
```

> ✅ **وضعیت فعلی**: کلید RSA واقعی شما در APK v1.2.0 (versionCode 3) قرار داده شده و
> فایل امضاشده در `download/fitup-bazaar-v1.2.0.apk` آماده آپلود است — نیازی به
> بازسازی ندارید مگر اینکه خودتان کلید را در پنل بازار عوض کنید.

> ⚠️ بدون کلید RSA، خرید درون‌برنامه‌ای **fail-closed** است: کاربر پیام خطای واضح می‌گیرد
> (هزینه‌ای رد نمی‌شود) — هرگز خرید بدون وریفای امضا انجام نمی‌شود.

### ۳.۲.۵ — کلید «قیمت پویا» (تخفیف در پرداخت درون‌برنامه‌ای) ✅

«کلید تخفیف پویا» که از پیشخان بازار گرفته‌اید = توکن سرویس **قیمت پویا (Dynamic
Pricing)** بازار. کاربرد: قیمت SKU در پنل بازار ثابت است؛ وقتی کاربر کد تخفیف یا
اعتبار ارتقا دارد، سایت مبلغ دقیق را سمت سرور در بازار ثبت می‌کند و اپ همان مبلغ
را می‌گیرد. این توکن در `.env` سرور سایت قرار دارد:

```env
BAZAAR_DYNAMIC_PRICE_TOKEN=nslCvAlYQSMDcTcBs83R2u_wEBIbVItzBA1EIPQUxWM
```

> اگر این توکن ست نشود، خرید درون‌برنامه‌ای با قیمت پایه SKU ادامه می‌یابد (بدون تخفیف) —
> خطایی رخ نمی‌دهد؛ فقط تخفیف اعمال نمی‌شود.

### ۳.۳ — دریافت توکن API پیشخان (برای راستی‌آزمایی سمت سرور)

پیشخان → برنامه فیتاپ → منوی راست → **«API پیشخان بازار»** → «دریافت توکن جدید»

سپس این توکن را در تنظیمات سایت فیتاپ بگذارید (پنل ادمین → تنظیمات، یا جدول SiteSetting):
- کلید: `bazaar_api_secret` — مقدار: توکن دریافتی
- یا در `.env` سرور: `BAZAAR_API_SECRET=...` و `BAZAAR_PACKAGE_NAME=ir.fittup.app`

> این توکن به سرور شما اجازه می‌دهد خرید کاربر را با API رسمی بازار راستی‌آزمایی کند
> (جلوگیری از جعل خرید) — endpoint آماده: `/api/payment/bazaar/purchase`
> (هم endpoint کالا و هم اشتراک را راستی‌آزمایی می‌کند؛ رد خرید refund شده)

### ۳.۴ — بازسازی APK با کلید RSA ✅ (v1.2.0 ساخته شده)

APK فعلی: `download/fitup-bazaar-v1.2.0.apk` (versionCode=3) — کلید RSA داخلش است.

اگر در آینده کلید/قابلیت را عوض کردید:

```bash
cd fitup-bazaar
export JAVA_HOME=/مسیر/به/jdk17
export ANDROID_HOME=/مسیر/به/android-sdk
./gradlew assembleRelease
# خروجی: app/build/outputs/apk/release/app-release.apk
```

⚠️ هر بار کلید/دامنه/قابلیت native را عوض کردید:
1. `versionCode` را یکی بالا ببرید (۴، ۵، …)
2. دوباره بیلد کنید
3. در پنل ادمین سایت، `app_latest_version_code` و `app_min_version_code` را همان عدد جدید کنید
4. APK را در بازار آپلود کنید (اپ قدیمی‌ها به‌روزرسانی را می‌بینند)

> فعلاً `app_latest/min_version_code = 3` تنظیم شده (در پنل ادمین قابل تغییر) — یعنی
> هر کس نسخه ۱.۰/۱.۱ (code 1/2) نصب دارد آپدیت اجباری می‌گیرد که فیکس‌های اسکرول/OTP/RSA را می‌گیرد.

## معماری فنی

```
┌─────────────┐     WebView      ┌──────────────┐
│  اپ بازار   │ ◄──────────────► │  سایت فیتاپ  │
│ (Kotlin)    │  پل‌های JS:       │ (Next.js)    │
│  پولکی      │  fitupBazaar-    │              │
│  2.2.0      │  Purchase/       │ /api/payment │
│  consume/   │  Restore/Notify/ │ /bazaar/     │
│  version    │  Download/Print  │ /purchase    │
└──────┬──────┘                  └──────┬───────┘
       │ purchaseProduct                │ راستی‌آزمایی با Developer API
       │ + consumeProduct               ▼
       ▼                          pardakht.cafebazaar.ir
  درگاه پرداخت بازار              (هدر CAFEBAZAAR-PISHKHAN-API-SECRET)
  (purchaseToken + امضای RSA)
```

فلوی خرید: کاربر در اپ → دکمه خرید پلن → `window.fitupBazaarPurchase(sku)` →
درگاه بازار باز می‌شود → پرداخت → purchaseToken به JS برمی‌گردد →
سایت به `/api/payment/bazaar/purchase` می‌فرستد → سرور با API بازار راستی‌آزمایی
می‌کند → اشتراک فعال می‌شود (همان منطق زرین‌پال: تمدید همان پلن روزهای باقیمانده
را حفظ می‌کند؛ advanced/ultimate → pending تا تکمیل پیش‌نیازها؛ تولید برنامه
پس‌زمینه؛ پاداش معرفی) → اپ خرید را consume می‌کند (برای تمدید بعدی).

فلوی بازیابی: اپ بالا می‌آید → پولکی وصل می‌شود → خریدهای consume-نشده →
`window.__fitupBazaarRestore([...])` → سایت هر توکن را به همان endpoint می‌فرستد
(idempotent) → بعد از موفقیت consume می‌شود.

نوتیف: polling نوتیف سایت (هر ۱۰/۳۰ ثانیه) → نوتیف جدید → `FitUpNative.showNotification` →
نوتیف سیستم اندروید (مجوز ۱۳+ فقط وقتی کاربر داخل سایت روی کارت «فعال‌سازی اعلان‌ها» بزند
درخواست می‌شود — نه در استارتاپ).
