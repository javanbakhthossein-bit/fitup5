# راهنمای اپ اندروید «اختصاصی» فیتاپ (نسخه سایت)

این اپ **جدا از اپ کافه‌بازار** است و فقط از خود سایت fittup.ir دانلود می‌شود:

| | اپ کافه‌بازار | اپ اختصاصی (این راهنما) |
|---|---|---|
| پکیج | `ir.fittup.app` | `ir.fittup.panel` |
| پرداخت | IAB بازار (پولکی) | درگاه خود سایت (زرین‌پال) داخل WebView |
| دانلود | فقط از بازار | `fittup.ir` → بخش «نصب اپلیکیشن» / منوی اپ پنل |
| شروع | `?screen=auth` (OTP) | `?screen=auth` (OTP) — دقیقا همان ساختار سایت |
| آپدیت | صفحه بازار + دیالوگ نیتیو | **مودال زیبا داخل سایت** + DownloadManager نیتیو |
| آیکون/نام | فیتاپ / لوگوی فیتاپ | فیتاپ / لوگوی فیتاپ (همان) |

## فایل‌ها

- `download/fitup-own-v1.2.2.apk` — نسخه ۱.۲.۲ امضاشده (keystore فیتاپ، همان بازار) — **موجود در بستهٔ v30**
- `public/downloads/fitup-own-v1.2.2.apk` + `public/downloads/fitup-own-version.txt` (= `1.2.2 5`) — داخل بستهٔ دیپلوی؛ deploy.sh خودش انتشار را انجام می‌دهد (idempotent)
- سورس کامل: پوشه `fitup-app/` (پروژه اندروید Gradle)
- `scripts/publish-own-app.ts` — انتشار نسخه جدید در DB + کپی APK
- `scripts/setup-android-toolchain.sh` — بازسازی تولچِین بیلد (JDK17 + SDK + Gradle در /tmp/toolchain)

## سیستم نسخه/آپدیت (بدون build مجدد!)

1. **انتشار نسخه جدید:** پنل مدیریت → تنظیمات سایت → «اپ اندروید اختصاصی فیتاپ» →
   فایل APK + نام نسخه (مثل `1.0.1`) + کد نسخه (عدد، **همیشه بالاتر از قبلی**) + تغییرات (هر خط یک مورد) → «انتشار نسخه جدید».
2. کاربرانی که نسخه قدیمی دارند، دفعه بعد که اپ را باز کنند **مودال زیبای «نسخه جدید فیتاپ آماده است!»** می‌بینند:
   - نسخه جدید + لیست تغییرات + حجم فایل
   - دکمه «دانلود نسخه جدید» → دانلود نیتیو (DownloadManager) → دیالوگ نصب
   - اگر «آپدیت اجباری» تیک خورده باشد، دکمه «بعداً» مخفی می‌شود
3. **تغییرات خودِ سایت هرگز نیازی به نسخه جدید APK ندارند** — اپ همه‌چیز را از سایت می‌خواند و
   همیشه به‌روز است (HTML تازه + assetهای hashدار). فقط تغییرات نیتیو (مجوزها، دامنه، قابلیت اندرویدی) نسخه جدید می‌خواهند.

## بیلد نسخه بعدی (در سرور/سندباکس)

```bash
# ۱) اگر تولچِین پاک شده:
bash scripts/setup-android-toolchain.sh   # → /tmp/toolchain (چند دقیقه)

# ۲) کد نسخه را در fitup-app/app/build.gradle.kts بالا ببرید:
#    versionCode = 2  /  versionName = "1.0.1"

# ۳) بیلد:
cd fitup-app
export JAVA_HOME=/tmp/toolchain/jdk17
export ANDROID_HOME=/tmp/toolchain/android-sdk
/tmp/toolchain/gradle-8.7/bin/gradle --no-daemon --max-workers=1 assembleRelease
# → app/build/outputs/apk/release/app-release.apk

# ۴) انتشار در DB (همان کار پنل ادمین، از خط فرمان):
bun scripts/publish-own-app.ts "1.0.1" 2
```

نکته رم: اگر Gradle با OOM کشته شد → dev server را ری‌استارت کنید (`kill <pid next-server>` —
supervisor خودش بالا می‌آورد) و `--max-workers=1` + `gradle.properties` کم‌مصرف حفظ شود.

## v1.2.2 — ریشه‌ای فیکس «دانلود نسخه جدید کار نمی‌کند» (بستهٔ v30 — فیکس گزارش مالک)

**باگ:** «دکمهٔ دانلود نسخه جدید (مودال آپدیت) و دکمهٔ دانلود اپ اندروید می‌نویسد دانلود
شروع شد ولی دانلود نمی‌شود». ریشه سه لایه بود:
1. **کوارک اندروید ۱۴+:** گیرندهٔ `ACTION_DOWNLOAD_COMPLETE` با `RECEIVER_NOT_EXPORTED`
   ثبت می‌شد و برادکست DownloadProvider به آن نمی‌رسید → دیالوگ نصب هیچ‌وقت باز نمی‌شد.
2. **دانلود نامرئی:** مقصد APK پوشهٔ خصوصی اپ است؛ بدون مجوز نوتیف هیچ نشانه‌ای دیده نمی‌شد.
3. **پیام بی‌شرط:** «شروع شد» حتی وقتی شروع نشده بود نمایش داده می‌شد.

**فیکس ریشه‌ای (دو لایه):**
- **سمت وب:** برای اپ‌های قدیمی‌تر از v1.2.2، دانلود با `intent://` به مرورگر بیرونی سپرده
  می‌شود (کروم دانلود + نوتیف + پیشنهاد نصب) — با دیپلوی v30 برای همهٔ اپ‌های نصب‌شده فوری درست می‌شود.
- **سمت نیتیو (این APK):** گیرنده با `RECEIVER_EXPORTED` (برادکست protected)، وضعیت دانلود
  در SharedPreferences + safety-net در onResume (پایان دانلود با بستن اپ هم گم نمی‌شود)،
  دیالوگ شکست با «تلاش دوباره / دانلود با مرورگر»، توست دقیق، چک زودهنگام خطا (۷ ثانیه).
- versionCode: 5 / versionName: 1.2.2 — MD5: `56e3cea480c92b89953611d1a0f8f856` (746,908 بایت)

## v1.2.1 — حذف ریشه‌ای پرمیشن پیامک (بستهٔ v29 — فیکس گزارش مالک)

**باگ:** در اندروید ۱۳+، پرمیشن `RECEIVE_SMS` برای اپ‌های خارج از گوگل‌پلی «محدود» است؛
سیستم اجازهٔ اعطا را کلاً می‌بندد و دیالوگ ترسناک **«App was denied access — Access to this
permission can put your personal and financial info at risk»** نشان می‌داد → هم مشتری می‌ترسید
و هم ورود خودکار OTP هیچ‌وقت کار نمی‌کرد.

**فیکس ریشه‌ای:** پرمیشن پیامک + receiver + دیالوگ درخواست + کارت «ورود خودکار با پیامک»
از هر دو اپ حذف شد. ورود خودکار کد حالا بدون هیچ پرمیشنی:
1. ورودی کد در سایت `autocomplete="one-time-code"` دارد → خود اندروید/کیبورد (Gboard، Samsung Keyboard)
   کد را به‌صورت پیشنهاد بالای کیبورد می‌آورد — یک لمس
2. اگر کاربر کد را کپی کند (دکمهٔ «کپی کد» نوتیف پیامک)، به‌محض برگشتن به اپ اتو-درج می‌شود
3. ورود دستی همیشه هم هست
- versionCode: 4 / versionName: 1.2.1 — MD5: `87efb8b1fb1269d3bfd46f9bbbb7db71` (743,236 بایت)

## v1.1.0 — مجوزها با مودال زیبا (درخواست مالک)

دسترسی‌ها **در زمان خودشان** و با یک **مودال انیمه‌دار جذاب** (برند فیتاپ: گوی آیکون تپنده + حلقه‌های نور + ورود فنری) گرفته می‌شوند — پیاده‌سازی مشترک در خود سایت (`permission-gate.ts` + `permission-gate-modal.tsx`)، پس تغییر متن/ظاهر مودال **بدون نسخه جدید APK** اعمال می‌شود:

| دسترسی | زمان درست | جریان |
|---|---|---|
| اعلان‌ها | بعد از ورود اول به پنل (فقط یک‌بار) | مودال → تأیید → پل `requestNotificationPermission` → دیالوگ سیستمی اندروید ۱۳+ |
| میکروفون | لحظهٔ ضبط ویس | مودال → getUserMedia → دیالوگ سیستمی |
| گالری | اولین انتخاب عکس/ویدیو | مودال توضیح → گالری باز (مجوز runtime لازم ندارد — SAF) |
| دوربین | لحظهٔ ضبط درون‌برنامه‌ای | رزرو (فعلاً دوربین از طریق گالری/دوربین گوشی) |

- دیالوگ تکراری نیتیو دوربین/میکروفون حذف شد (قبلاً دوبار پرسیده می‌شد)
- رفع باگ قواعد R8: پکیج `ir.fittup.panel` (قبلاً `ir.fittup.app` بود — پل JS در خروجی minify بی‌اثر می‌شد)
- اعلان‌های سیستم: polling نوتیف سایت → `showNotification` نیتیو (نوتیف چت/نیکا فیلتر — درخواست مالک)
- «قانونی بودن»: APK با keystore واقعی امضاشده (v2 scheme)، مجوزها حداقلی و هرکدام فقط با رضایت کاربر در لحظهٔ استفاده؛ هیچ دیتایی بدون اجازه جمع نمی‌شود. (نصب از منبع ناشناس برای هر APK خارج از استور — حتی بازار — یک تأیید سیستمی اندروید می‌خواهد؛ این رفتار استاندارد اندروید است نه هشدار مضر بودن)

## نکات فنی مهم

- **فایل APK در `uploads/apk/`** ذخیره و از `/api/app/own/download` سرو می‌شود (پشتیبانی Range + شمارنده دانلود).
- **آپلود فقط از پنل ادمین** (requireAdmin) — کاربر عادی فقط دانلود دارد.
- پرداخت داخل اپ: زرین‌پال/شاپرک داخل WebView باز می‌شوند (تا برگشت موفق به پنل) — شبکه‌های اجتماعی و سایت‌های دیگر در مرورگر بیرونی.
- OTP: پیشنهاد سیستم/کیبورد (`one-time-code`) + اتو-درج کلیپ‌بورد — بدون هیچ پرمیشن پیامک. دوربین/میکروفون فقط «در لحظهٔ استفاده» (همان سیاست‌های اپ بازار).
- نوتیف‌های سیستم از همان polling سایت + پل `showNotification` (نوتیف چت/نیکا فیلتر شده — درخواست مالک).
- خروج از حساب در اپ → صفحه OTP (نه لندینگ). لوگوی منو در اپ غیرفعال است (درخواست مالک).
