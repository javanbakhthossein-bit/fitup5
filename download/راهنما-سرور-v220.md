## گام ۱ — دیپلوی (کپی/پیست یک‌جا)

1. فایل `fitup-deploy-2026-10-08-v220.zip` را روی سرور آپلود کن (مثلاً به `/root`).
2. **کل بلاک زیر را یک‌جا کپی کن، در ترمینال سرور پیست کن و اینتر بزن:**

```bash
bash <<'FITUP_DEPLOY_220'
# ═══════════════════════════════════════════════════════════
#  فیتاپ v220 — دیپلوی (unzip + build اگر لازم + ری‌استارت)
#  مطمئن: پوشهٔ db و uploads دست‌نخورده می‌مانند
# ═══════════════════════════════════════════════════════════
set -e
APP_DIR="/var/www/fitup"
ZIP="/root/fitup-deploy-2026-10-08-v220.zip"

echo "── ۱) پشتیبان سریع از دیتابیس ──"
DBF=$(ls -t "$APP_DIR"/db/*.db 2>/dev/null | head -1 || true)
if [ -n "$DBF" ]; then
  cp "$DBF" "/root/fitup-db-backup-$(date +%Y%m%d-%H%M%S).db" && echo "   ✅ بکاپ دیتابیس در /root ذخیره شد"
fi

echo "── ۲) unzip زیپ v220 ──"
cd "$APP_DIR"
unzip -oq "$ZIP" -d /tmp/fitup-v220
# همه‌چیز جز db و uploads و .env و .next/cache از روی پوشهٔ استخراج‌شده کپی می‌شود
rsync -a --exclude 'db/' --exclude 'uploads/' --exclude '.env' --exclude '.next/cache/' /tmp/fitup-v220/ "$APP_DIR"/
rm -rf /tmp/fitup-v220
echo "   ✅ فایل‌های v220 جایگزین شدند"

echo "── ۳) نصب وابستگی (فقط اگر package.json عوض شده باشد) ──"
cd "$APP_DIR"
if command -v bun >/dev/null 2>&1; then
  bun install --frozen-lockfile >/dev/null 2>&1 || bun install >/dev/null 2>&1 || true
elif command -v npm >/dev/null 2>&1; then
  npm ci >/dev/null 2>&1 || npm install >/dev/null 2>&1 || true
fi

echo "── ۴) اگر زیپ شامل بیلد آماده است، skip؛ وگرنه build ──"
if [ ! -d "$APP_DIR/.next" ]; then
  echo "   .next پیدا نشد — build می‌گیرم..."
  if command -v bun >/dev/null 2>&1; then bun run build; else npm run build; fi
fi

echo "── ۵) ری‌استارت pm2 ──"
(runuser -u $(stat -c '%U' "$APP_DIR") -- pm2 restart fitup 2>/dev/null) || \
(su - $(stat -c '%U' "$APP_DIR") -c "pm2 restart fitup" 2>/dev/null) || \
pm2 restart fitup

sleep 3
echo ""
echo "── چک نهایی ──"
CODE=$(curl -s -o /dev/null -w "%{http_code}" http://localhost:3000/ || echo "000")
echo "   صفحهٔ اصلی: HTTP $CODE"
if [ "$CODE" = "200" ]; then
  echo ""
  echo "🎉 v220 با موفقیت دیپلوی شد!"
  echo "   حالا فقط گام ۲ (Submit Sitemap در گوگل سرچ کنسول) مانده است."
else
  echo ""
  echo "⚠️ کد $CODE — چند ثانیه صبر کن و دوباره بزن: curl -s -o /dev/null -w \"%{http_code}\" http://localhost:3000/"
  echo "   اگر هنوز 200 نشد، خروجی «pm2 logs fitup --lines 30» را برای من بفرست."
fi
FITUP_DEPLOY_220
```

## گام ۲ — Submit دوبارهٔ Sitemap در گوگل (اگر هنوز نکردی)

1. برو به [Google Search Console](https://search.google.com/search-console) → property دامنهٔ `fittup.ir`
2. منوی چپ: **Sitemaps**
3. تایپ کن: `sitemap.xml` → دکمهٔ **Submit**
4. تمام — گوگل خودش در روزهای آینده همهٔ ~۲۲۴۵ صفحه را بررسی می‌کند.

## در v220 چه چیزهایی درست شد؟ (توضیح ساده)

### ۱) لگ اسکرول لندینگ — سه علت پیدا و رفع شد

| علت | توضیح ساده | فیکس |
|---|---|---|
| انیمیشن‌های نامرئی | ۵ انیمیشن «برق طلایی» همیشه روشن بودند — حتی وقتی آن بخش از صفحه اصلاً دیده نمی‌شد. مجموعشان گوشی را خسته می‌کرد. | حالا فقط وقتی آن بخش واقعاً در دید است انیمیت می‌شود. کارت‌های پرمیوم فقط موقع هاور. |
| دانلود وسط اسکرول | برنامه بلافاصله شروع می‌کرد به دانلود ۱۳ فایل سنگینِ پنل — دقیقاً وسط اولین اسکرول کاربر → پرش فریم. | حالا صبر می‌کند تا کاربر کلیک/لمس کند یا اسکرولش آرام بگیرد. اسکرول اول هیچ رقیبی ندارد. |
| شیشه‌ایِ منوی بالا در موبایل | افکت blur روی منوی ثابت بالای صفحه، گران‌ترین افکت برای اسکرول موبایل است. | در موبایل با پس‌زمینهٔ مات ساده جایگزین شد (روی دسکتاپ همان شیشه‌ای قبلی — قشنگ‌تر). |

+ بهبود اضافه: انیمیشن دکمهٔ چت نیکا از جاوااسکریپت به CSS خالص منتقل شد (فقط transform — روی چیپ گرافیکی، صفر هزینه)، throttle اسکرول منو با requestAnimationFrame، و preload تصویر هیرو با فرمت درست (AVIF/WebP — دیگر دانلود دوگانه اتفاق نمی‌افتد).

### ۲) «…» در نام حرکات جم‌مود — رفع شد

نام‌های بلند حرکات (مخصوصاً داخل سوپرست/تری‌ست/جاینت‌ست) قبلاً با «…» کوتاه می‌شدند. حالا در **همه‌جا** کامل و چندخطی نمایش داده می‌شوند:

- جم‌مود → تمرین امروز (کارت حرکت، ردیف‌های سوپرست، چیپ روز، خط هدف ست)
- جلسهٔ تمرین عادی (active-workout-session) → ردیف‌های سوپرست
- جلسهٔ چالش‌ها → عنوان چالش و روز

### ۳) «سرعت کل سایت» — توضیح مهم

- **Gzip فعال و سالم است** (تست مستقیم انجام شد — صفحات و فایل‌ها فشرده می‌شوند). Gzip سرعت دانلود را *بالا* می‌برد؛ ربطی به روانی اسکرول ندارد.
- کندی حس‌شده همان سه علت بالا بود که اثرشان روی همهٔ صفحات دیده می‌شد (چون منوی بالا و انیمیشن‌ها و دانلود چانک‌ها مشترک‌اند) — با v220 هر سه رفع شدند.
- اگر بعد از دیپلوی v220 باز جایی حس کندی داشتی، اسم دقیق صفحه را بگو تا مخصوص همان را بررسی کنم.
