## لینک‌های پیامک

- `LINK` در قالب‌های تمدید = کد کوتاه `r/XXXXXXXX` (≤۲۵ کاراکتر — ضد خطای ۱۱۴) → 302 به `go/renew?t=…` → **لینک هوشمند**: اپ نصب باشد اپ باز می‌شود (اسکیم `fitup://`)، نبود → صفحهٔ تمدید مجزا `fittup.ir/renew?t=…` که **بدون لاگین** باز می‌شود: مبلغ نهایی با کد تخفیف ازقبل‌ساخته، درگاه آماده، پیشنهادهای ارتقا.
- `LINK` ترک-درگاه = `r/XXXXXXXX` → `go/plans?offer=<کد داخلی>` → صفحهٔ پلن‌ها با قیمت تخفیف‌خورده + شمارش معکوس زنده.
- نردبان خودترمیم پارامتر: اگر قالب در پنل متغیر کمتری داشته باشد، اولین ترکیب سازگار ارسال می‌شود (`[NAME+CODE+LINK]→[NAME+CODE]→[NAME]→[]` و مشابه).
- گارد مرکزی: هر پارامتر ≤۲۵ کاراکتر (NAME کوتاه می‌شود؛ پارامتر بلندِ غیر NAME حذف) — خطای ۱۱۴ ساختاراً ناممکن است.
- دداپ‌ها: هر چرخه/پرداخت فقط یک بار (کلید با شناسهٔ اشتراک/پرداخت) — اجرای مکرر هرگز پیامک تکراری نمی‌فرستد.

## کدهای تخفیف — قواعد اعتبارسنجی (سمت سرور)

- کد هر کاربر **یکتا و یک‌بارمصرف** است؛ کد قالب ۳ (۴۶۱۲۹۱) و ۱۶ (۶۱۲۹۶۴) **فقط اولین خرید** (هر خرید قبلی → رد در پرداخت).
- کدهای ۸ و ۱۷ (تمدید) **همهٔ پلن‌ها**؛ کد ترک-درگاه یک‌بارمصرف و فقط درگاه.
- درصد همه از پنل مدیر (تنظیمات) قابل تغییر است و روی کدهای استفاده‌نشدهٔ موجود هم اعمال می‌شود (اعتبارشان از زمان ساخت می‌سوزد — تمدید نمی‌شود).
- کد تخفیف اختصاصی کاربر بر کد عمومی دستی **ارجحیت** دارد؛ **تخفیف ۱۰٪ صفحهٔ تحلیل روی همهٔ این‌ها (بعد از کد و اعتبار ارتقا) اضافه محاسبه می‌شود** (v200: حتی اگر پرداختِ معلقِ قدیمیِ بدون تخفیف وجود داشته باشد، خرید جدید با تخفیف ساخته می‌شود — ریشه‌کنیِ «درگاه با مبلغ کامل»).
- قیمت کارت‌های پلن در پنل برای کاربرِ دارای کد فعال، با قیمت تخفیف‌خورده نمایش داده می‌شود (خط‌خورده + نهایی + چیپ تخفیف).

## تست ارسال

**پنل مدیر ← تنظیمات ← «پیامک‌های سیستمی فیتاپ» ← شماره را وارد کن ← ارسال تستی همهٔ قالب‌ها** — نتیجهٔ تک‌تک (با نردبان خودترمیم) نمایش داده می‌شود.

ابزار بازیابی بعد از دیپلوی (روی سرور):
```bash
cd /var/www/fitup
bun run scripts/resend-sms.ts --dry-run   # گزارش بدون ارسال
bun run scripts/resend-sms.ts             # ارسال واقعی پیامک‌های خطادار
```

## 🩺 OTP — نکته‌های عملیاتی

- زنجیرهٔ fallback دوطرفه (raw ↔ قالب) + مدارشکن ۶۰ دقیقه‌ای بعد از شکست bulk.
- خطای «۱۰۱ — شماره خط نامعتبر» فقط مسیر bulk را می‌کشد؛ OTP از مسیر قالب می‌رود. برای WebOTP: `SMSIR_LINE=شماره_خط` در .env سرور.
- لاگ: `pm2 logs fitup --lines 100 --nostream | grep send-otp`

## تاریخچهٔ تغییرات این سند

- **v200 (اکتبر ۲۰۲۶):** بازنویسی کامل به‌عنوان مرجع مالک — جدول انقضای طلایی کدها (۴۸ ساعت پیامکی / ۲ ساعت ترک-درگاه / ۳۰ دقیقه صفحهٔ تحلیل)، متن کامل همهٔ قالب‌ها + پیشنهاد همگام‌سازی، جدول متغیرهای env کامل (۱۹ سناریو)، ریشه‌کنی باگ تخفیف صفحهٔ تحلیل در مدال خرید اینستاگرام (v200).
- **v53:** اعتبار همهٔ کدهای پیامکی ۱۴/۳۰ روز → **۴۸ ساعت** (دیریکتیو مالک) + کد ترک-درگاه ۲۴۸۹۴۵ (۲ ساعته).
- **v48:** لینک‌های کوتاه `r/XXXXXXXX` (فیکس خطای ۱۱۴) + پنجرهٔ ۹۰ روزهٔ قالب ۶۶۹۰۶۸.
- **v47:** قالب‌های ۶۱۲۹۶۴ و ۸۸۳۳۲۵ + لینک هوشمند `go/renew` + درصد تمدید ۳۰٪.
- **v45:** OTP فقط از `/v1/send/verify`.
- **v43/v42:** گارد نام («ورزشکار» برای بی‌نام در ۶۶۹۰۶۸؛ بقیهٔ قالب‌ها بدون نام ارسال نمی‌شوند).
