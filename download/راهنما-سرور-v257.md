> زیپ: `fitup-deploy-2026-11-04-v257.zip` — فقط سورس کد (عکس/ویدیو/APK/DB روی سرور موجود است)

## ۱) این آپدیت چه کرد؟ (خلاصهٔ مالک)

### باگ ۱ — خطای «Minified React error #418» در لاگ مدیر (ریشه‌یابی قطعی و رفع)

لاگ پنل دو رکورد تازه داشت (`?screen=panel&tab=programs` موبایل اپ بازار و `/foods` ویندوز).
ریشه‌یابی با دیکد کردن چانک‌های production انجام شد:

- **جنس خطا:** خطای هیدریشن React — «server rendered HTML didn't match the client» — یعنی وسط
  walk هیدریشن، یک گره DOM غیرمنتظره در `<head>` دیده می‌شد و React همان لحظه درخت را از نو
  کلاینت‌رندر می‌کرد (فلش کوتاه؛ صفحه خراب نمی‌شد).
- **ریشه:** لودر Microsoft Clarity (v240) بعد از `load + ۱۲۰۰ms` با `requestIdleCallback({timeout:4000})`
  تگش را به head اضافه می‌کرد. `requestIdleCallback` بین تایم‌اسلایس‌های رندر همزمان React «idle»
  می‌بیند (رندر concurrent عمداً بین اسلایس‌ها وقفه می‌گذارد) ⇒ تزریق دقیقاً وسط هیدریشن.
  برای همین پراکنده بود: هر صفحه/هر مرورگری ممکن بود قرعه بیفتد (۱۴ سشن در ۳ هفته، Chrome ۱۳۱→۱۵۶).
- **فیکس سه‌لایهٔ v257:**
  1. سیگنال سراسری `window.__fitupHydrated` — در اولین effect بعد از پایان هیدریشن ریشه ست می‌شود.
  2. لودر Clarity حالا به‌جای قرعه‌کشی rIC، منتظر همین سیگنال می‌ماند (سقف ~۱۰ ثانیه؛ اگر هیدریشن
     هرگز نیفتاد بعد از سقف لود می‌شود — هیچ چیزی برای شکستن باقی نمی‌ماند).
  3. تزریق manifest iOS (تنها تزریق parse-time باقیمانده در head) هم به همین گیت منتقل شد.

### باگ ۲ — «صفحهٔ دستیار هوشمند در پنل مدیر در موبایل اسکرول نمی‌شود»

- **بازتولید و ریشه:** دو عامل با هم: ① ارتفاع تب هرگز «بسته» نبود (مینیمم 95vh فقط کفِ ارتفاع بود)
  ⇒ ناحیهٔ پیام‌ها با محتوا رشد می‌کرد و خودش هیچ‌وقت کانتینر اسکرول نمی‌شد؛ ② قانون
  `overscroll-behavior: contain` (دیرکتیو v44 — «فقط صفحه زیرش اسکرول نشه») روی همان ناحیه،
  زنجیرهٔ لمس/چرخ به کانتینر بیرونی را هم می‌بست ⇒ لمس روی چت عملاً «یخ» می‌زد.
- **فیکس:** همان الگوی چت سمت کاربر (اثبات‌شده در موبایل): شلِ با ارتفاع بسته `calc(100vh-128px)`
  (+ ارتقای خودکار به `100dvh` در مرورگرهای جدید؛ فال‌بک vh برای WebViewهای قدیمی مثل کروم ۸۳)،
  بنر آمار/پیشنهادهای سریع/جعبهٔ پیام با `shrink-0` همیشه ثابت و دیدار، و پیام‌ها داخل خودش اسکرول.
- تست شد: موبایل 390×844 (لمس/چرخ روی چت اسکرول می‌شود)، دسکتاپ، و تب‌های دیگر پنل (اسکرولشان
  دست‌نخورده سالم است).

## ۳) دیپلوی (مثل همیشه)

```bash
cd /var/www/fitup
# بکاپ DB قبل از هر کاری
cp db/custom.db db/custom.db.pre-v257-$(date +%H%M)
# باز کردن زیپ روی سورس موجود (رسانه‌ها دست نمی‌خورند — در زیپ نیستند)
unzip -o fitup-deploy-2026-11-04-v257.zip -d /var/www/fitup
bun install
bun run build   # یا ری‌استارت سرویس طبق روال قبلی
pm2 restart fitup   # یا سرویس معادل
```

## ۴) راستی‌آزمایی بعد از دیپلوی (۵ دقیقه)

1. `/foods` و `/exercises` را در موبایل باز کنید — کنسول مرورگر باید بدون هرگونه
   «Hydration failed / Minified React error #418» باشد. (در ۱۰ دقیقه اول هیچ تگ Clarity
   دیرتر از قبل لود نمی‌شود؛ فقط بعد از پایان هیدریشن — رفتار تحلیل رفتار Clarity تغییری نمی‌کند.)
2. پنل مدیر → تب «دستیار هوشمند» در موبایل: پیام بدهید تا مکالمه بلند شود — پیام‌ها داخل همان
   کادر اسکرول می‌شوند و جعبهٔ پیام/پیشنهادها همیشه پایین ثابت‌اند؛ بنر آمار بالای تب ثابت است.
3. تب‌های دیگر پنل (کاربران/مالی) — اسکرول مثل قبل.
4. مقدار `window.__fitupHydrated` در کنسول باید `true` باشد (ابزار عیب‌یابی — روی production هم فعال است، بی‌ضرر).
