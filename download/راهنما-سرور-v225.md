# راهنمای سرور — دیپلوی v225 (فیتاپ)

> 📥 **لینک دانلود زیپ v225** را دستیار در چت می‌دهد (۴۸ ساعت اعتبار دارد؛ منقضی شد، فقط بگو «لینک جدید بده»). داخل پیش‌نمایشِ کوچک دانلود گاهی بلاک می‌شود؛ حتماً با دکمهٔ **Open in New Tab** در تب کامل باز کن.

> تاریخ: 2026-10-08 — محتوای v225: **🚫 ریشهٔ نهایی و واقعیِ صفحهٔ «اتصال برقرار نیست / فیتاپ به اینترنت نیاز دارد» پیدا و از پایه درآورده شد** (همان که بعد از ویدیو می‌آمد و بعد اسپلش و بعد داشبورد) + دو APK جدید (اختصاصی 1.19.1 / بازار 1.17.1).

## این نسخه در یک نگاه — این بار واقعاً ریشه را پیدا کردم

**مشکلی که گزارش کردی (۱۰ بار!):** بعد از تمام شدن ویدیو، صفحهٔ «اتصال اینترنت برقرار نیست — فیتاپ به اینترنت نیاز دارد» می‌آمد، بعد اسپلش، بعد داشبورد. اینترنتی هم که وصله و هیچ قطعی واقعی‌ای در کار نیست.

**چرا فیکس‌های قبلی کار نکرد؟**
فیکس قبلی (v224) لایهٔ **نیتیو اپ** را کامل کرده بود — و واقعاً هم هیچ خطایی از سمت خود اپ نشان داده نمی‌شد. اما حالا دقیقاً فهمیدم آن صفحه از **یکی دیگر می‌آمد**: صفحهٔ آفلاینِ داخل **سرویس‌ورکرِ سایت** (یک فایل به اسم `sw.js` که از خود سایت fittup.ir داخل هر دو اپ لود می‌شود). یعنی صفحه خطا اصلاً از اپ نبود — از **سایتِ داخل اپ** بود؛ برای همین هر چقدر اپ را فیکس می‌کردیم، آن صفحه هنوز می‌آمد.

**مکانیزم دقیق باگ (خلاصهٔ ساده):**
1. موقع باز کردن اپ، اولین درخواستِ بارگذاری صفحه گاهی یک‌بار شکست می‌خورد (لحظهٔ اتصال DNS/سوکت — حتی با اینترنت سالم، چند صدم ثانیه طول می‌کشد).
2. سرویس‌ورکر به‌جای صبر، فوراً صفحهٔ «اتصال برقرار نیست» را می‌ساخت (با کد ۵۰۳).
3. این پاسخ از دید اپ «خطای شبکه» نیست — پس اپ فکر می‌کرد صفحه آماده است، ویدیو که تمام می‌شد همان صفحه نمایان می‌شد.
4. بعد صفحهٔ خطا خودش چند ثانیه بعد تلاش مجدد می‌کرد → وصل می‌شد → اسپلش → داشبورد. دقیقاً همان چیزی که می‌دیدی.

**چه کردم (سه لایه، دیگر هیچ راهی برای دیدنِ آن صفحه نیست):**
1. **سرویس‌ورکر حالا صبور شد:** هر بار بارگذاری صفحه تا **۳ تلاش پشت‌سرهم** (با فاصله) انجام می‌دهد — تقریباً همهٔ شکست‌های لحظه‌ای بی‌صدا جذب می‌شوند و کاربر اصلاً چیزی نمی‌بیند.
2. **صفحهٔ خطا پاک شد، اسپلش فیتاپ نشست:** حتی اگر هر ۳ تلاش شکست بخورد، دیگر هیچ صفحهٔ خطایی وجود ندارد — همان **اسپلش خود فیتاپ** (لوگو + فیتاپ + شعار + اسپینر) نمایش داده می‌شود و هر ثانیه بی‌صدا چک می‌کند؛ به‌محض وصل شدن، خودکار به همان صفحه برمی‌گردد. صفر کلمهٔ خطا، صفر دکمه.
3. **ضریب اطمینان در خود اپ‌ها (بیلد جدید):** هر دو اپ حالا اگر پاسخ «۵۰۳/۵xx» از سایت ببینند، می‌فهمند آن صفحه واقعی نیست → اسپلش برند می‌ماند + حلقهٔ اتصال خودکار → تا لود واقعی، کاربر فقط اسپلش می‌بیند.
4. **یک باگ حلقه‌ای هم رفع شد:** مکانیزم «تلاش مجدد» صفحهٔ خطای قبلی از کش جواب الکی می‌گرفت و باعث تکرار/لَگ می‌شد — حالا پروب کاملاً مستقیم و بدون کش است.

⭐ **نکتهٔ مهم:** فیکس شمارهٔ ۱ و ۲ **روی سرور** است — یعنی با همین دیپلوی، حتی **گوشی‌هایی که اپ قدیمی دارند** (بدون آپدیت) هم دیگر هرگز آن صفحه را نمی‌بینند. بیلدهای جدید فقط ضریب اطمینان لایهٔ نیتیو را ۱۰۰٪ می‌کنند.

## گام ۱ — دیپلوی (کپی/پیست یک‌جا)

1. فایل `fitup-deploy-2026-10-08-v225.zip` را روی سرور آپلود کن (مثلاً به `/root`).
2. **کل بلاک زیر را یک‌جا کپی کن، در ترمینال سرور پیست کن و اینتر بزن:**

```bash
bash <<'FITUP_DEPLOY_225'
# ═══════════════════════════════════════════════════════════
#  فیتاپ v225 — دیپلوی (unzip + ری‌استارت)
#  مطمئن: پوشهٔ db و uploads و .env دست‌نخورده می‌مانند
# ═══════════════════════════════════════════════════════════
set -e
APP_DIR="/var/www/fitup"
ZIP="/root/fitup-deploy-2026-10-08-v225.zip"

echo "== ۱) بکاپ سریع از نسخهٔ فعلی =="
tar -czf /root/fitup-backup-before-225.tar.gz -C "$APP_DIR" . 2>/dev/null || true

echo "== ۲) خالی کردن سورس قدیمی (بدون db/uploads/.env) =="
find "$APP_DIR" -mindepth 1 -maxdepth 1 \
  ! -name 'db' ! -name 'uploads' ! -name '.env' ! -name '.next' \
  -exec rm -rf {} +

echo "== ۳) باز کردن زیپ v225 =="
unzip -o -q "$ZIP" -d "$APP_DIR"

echo "== ۴) نصب وابستگی‌ها (اگر لازم شد) =="
cd "$APP_DIR"
[ -d node_modules ] || bun install --production=false

echo "== ۵) ری‌استارت اپ =="
pm2 restart fitup || pm2 start "bun run start" --name fitup
sleep 6
pm2 status fitup

echo "== ۶) چک سلامت =="
sleep 4
CODE=$(curl -s -o /dev/null -w "%{http_code}" http://localhost:3000/)
echo "HTTP / => $CODE (باید 200 باشد)"
curl -s http://localhost:3000/sw.js | head -c 200 | grep -q "fitup-v16" \
  && echo "SW v225 فعال است ✔" || echo "⚠ سرویس‌ورکر هنوز قدیمی است — چند ثانیه بعد دوباره چک کن"
echo "== پایان دیپلوی v225 ✔ =="
FITUP_DEPLOY_225
```

3. آخرِ خروجی باید ببینی: `HTTP / => 200` و `SW v225 فعال است ✔`.
