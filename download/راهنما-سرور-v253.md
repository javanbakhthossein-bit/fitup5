# راهنمای سرور v253 — افزودن غذاهای جدید به بانک کالری (بعد از دیپلوی)

## چرا بعد از دیپلوی تعداد غذاها عوض نشد؟

شمارندهٔ تعداد غذاها در کل سایت (لندینگ، متا تگ‌ها، صفحهٔ /foods) **پویا** است و زنده از دیتابیس می‌خواند (`FoodLibrary.count()` با کش ۶۰ ثانیه‌ای).

۶۰۷ غذای جدید نسخهٔ ۲۵۳ (برندهای ایرانی مثل کاله/مهرام/پگاه، USDA و…) در **دیتابیس** ساکن هستند، نه در کد. زیپ دیپلوی عمداً هرگز دیتابیس زندهٔ سرور را دست نمی‌زند (حفاظ دیتای کاربران) — پس دیپلوی کد، کافی نیست و باید یک‌بار سه اسکریپت seed اجرا شوند.

خبر خوب: این سه اسکریپت **داخل همان زیپ v253 هستند** و چون زیپ را روی سرور باز کرده‌اید، همین حالا روی سرور موجودند. هیچ فایل جدیدی لازم نیست آپلود کنید.

## مراحل اجرا (روی سرور)

```bash
cd /var/www/fitup          # همان پوشه‌ای که زیپ دیپلوی v253 در آن باز شده

# ۱) توقف موقت سرویس (حدود یک دقیقه)
pm2 stop fitup

# ۲) بکاپ امنیتی دیتابیس
mkdir -p db/backups
cp db/custom.db "db/backups/custom-pre-foods-v253-$(date +%Y%m%d-%H%M).db"

# ۳) اجرای سه اسکریپت seed (به همین ترتیب)
bun run scripts/seed-foods-v253-part1.ts
bun run scripts/seed-foods-v253-part2.ts
bun run scripts/seed-foods-v253-part3.ts

# ۴) راه‌اندازی مجدد
pm2 start fitup
```

## خروجی مورد انتظار

هر اسکریپت در آخر یک خط گزارش چاپ می‌کند:

```
before=1580 rowsInScript=... added=... TOTAL=...
```

- `TOTAL` نهایی باید به حدود **۲۱۸۷** برسد (اگر دیتابیس سرور از قبل ردیف‌های بیشتری داشته باشد، کمی بیشتر است — طبیعی است).
- اجرای تکراری هر سه اسکریپت **بی‌ضرر** است (غذاهای تکراری با نام یکسان اضافه نمی‌شوند).
- هیچ چیزی حذف نمی‌شود؛ کاربران، سفارش‌ها و بقیهٔ دیتا دست‌نخورده می‌مانند.

## راستی‌آزمایی

1. صفحهٔ `/foods` و شمارندهٔ لندینگ را باز کنید — باید عدد جدید را ببینید (کش ۶۰ ثانیه‌ای دارد؛ بعد از `pm2 start` فوری است).
2. شمارش مستقیم دیتابیس (اختیاری):

```bash
cd /var/www/fitup && bun -e "const{PrismaClient}=require('@prisma/client');const db=new PrismaClient();db.foodLibrary.count().then(c=>{console.log('FoodLibrary =',c);return db.\$disconnect()})"
```

## اگر خواستید برگردید (rollback)

```bash
pm2 stop fitup
cp "db/backups/custom-pre-foods-v253-<زمان>.db" db/custom.db
pm2 start fitup
```

## نکته‌های امنیتی

- اسکریپت‌ها فقط **افزودن/کالیبره‌کردن** انجام می‌دهند (نام تکراری = رد شدن).
- بخش «کالیبراسیون» در part2 مقدار کالری/درشت‌مغذی چند آیتم موجود را با منابع استاندارد (USDA) به‌روز می‌کند — این تغییر عمدی و درست است.
- بقیهٔ موارد v253 (ریبال زیبال، دیپ‌لینک اپ، تغییر مقدار واحد غذا، «وی» مکمل‌ها، حذف چیپ روزهای پلن) **کد** هستند و با همین دیپلوی فعال شده‌اند؛ فقط بانک غذا به این قدم سروری نیاز دارد.
