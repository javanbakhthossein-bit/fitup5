# راهنمای دیپلوی v228 — صفر شدن خطاهای جاوااسکریپت (ممیزی Clarity)

**تاریخ:** ۱۸ مهر ۱۴۰۴ (2026-10-09) — نسخهٔ سایت: 228.0.0

## این نسخه چیست؟ (توضیح ساده)

در ۲۴ ساعت گذشته Clarity سه نوع خطا دیده بود. ممیزی کامل انجام شد و **هر سه از
منابع خارجی بودند، نه کد فیتاپ** — و حالا هر سه از دید Clarity هم حذف شده‌اند:

| خطای Clarity | تعداد | منبع واقعی | کار v228 |
|---|---|---|---|
| `Invalid regular expression: invalid group specifier name` | ۹ | اسکریپت‌های تزریقی خارجی (مرورگر درون‌برنامه‌ای اینستاگرام و مشابه) روی آیفون‌های با iOS قدیمی — **راستی‌آزمایی شد: هر ۲۸ چانک سایت + اسکریپت‌های inline + حتی SDK خود Clarity صفر lookbehind دارند** | گارد سرِ head آن را از دید Clarity حذف می‌کند + گیت بیلد جلوی رگرسیون آینده را می‌گیرد |
| `Script error.` | ۸ | خطای cross-origin اسکریپت‌های تزریقی خارجی (مرورگر عمداً جزئیات را مخفی می‌کند — هیچ‌وقت قابل رفع نیست چون کد ما نیست) | از دید Clarity حذف می‌شود |
| `Error invoking postMessage: Java object is gone` | ۱ | لاگر داخلی مرورگر درون‌برنامه‌ای اینستاگرام در اندروید (مستند در error-noise از v37) | از دید Clarity حذف می‌شود |

**نکتهٔ مهم:** خطاهای واقعیِ اپ هیچ‌وقت فیلتر نمی‌شوند — فقط همین امضاهای نویزِ
شناسنامه‌دارِ خارجی. لاگ خطای خود سایت (که از همیشه صفر خطای regex داشته) حالا
حتی خطاهای «پیش از هیدریشن» را هم می‌بیند (بافر زودهنگام) — یعنی دیدِ ما از
Clarity کامل‌تر شد، نه کمتر.

## تغییرات فنی (برای سابقه)

1. `src/app/layout.tsx` — گارد زودهنگام خطا (ES5) قبل از Clarity:
   نویز → `preventDefault` (+ `stopImmediatePropagation` برای نویز محض) →
   `window.onerror` کلاریتی هرگز فراخوانی نمی‌شود؛ خطاهای chunk فقط
   `preventDefault` می‌شوند تا زنجیرهٔ ریکاوری reload دست‌نخورده بماند؛
   خطاهای واقعی کاملاً عبور می‌کنند.
2. `src/components/fitness/error-capture.tsx` — شستشوی بافر خطاهای
   پیش‌از‌هیدریشن (`window.__fitupEarlyErrs`) در اولین mount.
3. `scripts/build-deploy-zip.mjs` — گیت `[legacy-regex]`: اگر خروجی production
   یا بذرِ اپ‌ها lookbehind داشته باشد بسته‌بندی متوقف می‌شود (exit 1).

## دیپلوی (دو گام، همان همیشه)

```bash
cd /var/www/fitup

# ۱) پشتیبان سریع از نسخهٔ فعلی
cp -r .next .next.old-$(date +%s) 2>/dev/null || true

# ۲) باز کردن بسته روی نسخهٔ جدید
unzip -o /tmp/fitup-deploy-2026-10-09-v228.zip -d /tmp/fitup-v228
rsync -a --exclude 'node_modules' --exclude '.next' /tmp/fitup-v228/ /var/www/fitup/

cd /var/www/fitup
bun install --frozen-lockfile 2>/dev/null || bun install
bunx prisma generate
bun run build 2>&1 | tail -5

# ۳) جابجایی بیلد و ری‌استارت
rm -rf .next.new && mv .next .next.old && mv .next.new .next 2>/dev/null || true
pm2 restart fitup && pm2 save
```

⚠️ اگر روی سرور الگوی `.next.new` ندارید، همان الگوی دیپلوی همیشگی خودتان
(بند DEPLOY.md) را بزنید — تغییری در دیتابیس و env نیامده است.
