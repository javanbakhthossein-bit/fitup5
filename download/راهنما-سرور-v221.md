| گام | کار | زمان |
|---|---|---|
| ۱ | آپلود و unzip کردن زیپ v221 + ری‌استارت (کپی/پیست یک‌جا) | ~۵ دقیقه |

## گام ۱ — دیپلوی (کپی/پیست یک‌جا)

1. فایل `fitup-deploy-2026-10-08-v221.zip` را روی سرور آپلود کن (مثلاً به `/root`).
2. **کل بلاک زیر را یک‌جا کپی کن، در ترمینال سرور پیست کن و اینتر بزن:**

```bash
bash <<'FITUP_DEPLOY_221'
# ═══════════════════════════════════════════════════════════
#  فیتاپ v221 — دیپلوی (unzip + build اگر لازم + ری‌استارت)
#  مطمئن: پوشهٔ db و uploads دست‌نخورده می‌مانند
# ═══════════════════════════════════════════════════════════
set -e
APP_DIR="/var/www/fitup"
ZIP="/root/fitup-deploy-2026-10-08-v221.zip"

echo "── ۱) پشتیبان سریع از دیتابیس ──"
DBF=$(ls -t "$APP_DIR"/db/*.db 2>/dev/null | head -1 || true)
if [ -n "$DBF" ]; then
  cp "$DBF" "/root/fitup-db-backup-$(date +%Y%m%d-%H%M%S).db" && echo "   ✅ بکاپ دیتابیس در /root ذخیره شد"
fi

echo "── ۲) unzip زیپ v221 ──"
cd "$APP_DIR"
unzip -oq "$ZIP" -d /tmp/fitup-v221
# همه‌چیز جز db و uploads و .env و .next/cache از روی پوشهٔ استخراج‌شده کپی می‌شود
rsync -a --exclude 'db/' --exclude 'uploads/' --exclude '.env' --exclude '.next/cache/' /tmp/fitup-v221/ "$APP_DIR"/
rm -rf /tmp/fitup-v221
echo "   ✅ فایل‌های v221 جایگزین شدند"

echo "── ۳) نصب وابستگی (فقط اگر package.json عوض شده باشد) ──"
cd "$APP_DIR"
if command -v bun >/dev/null 2>&1; then
  bun install --frozen-lockfile >/dev/null 2>&1 || bun install >/dev/null 2>&1 || true
elif command -v npm >/dev/null 2>&1; then
  npm ci >/dev/null 2>&1 || npm install >/dev/null 2>&1 || true
fi

echo "── ۴) اگر زیپ شامل بیلد آماده است، skip؛ وگرنه build ──"
if [ ! -d "$APP_DIR/.next" ]; then
  echo "   .next پیدا نشد — build می‌گیرم..."
  if command -v bun >/dev/null 2>&1; then bun run build; else npm run build; fi
fi

echo "── ۵) ری‌استارت pm2 ──"
(runuser -u $(stat -c '%U' "$APP_DIR") -- pm2 restart fitup 2>/dev/null) || \
(su - $(stat -c '%U' "$APP_DIR") -c "pm2 restart fitup" 2>/dev/null) || \
pm2 restart fitup

sleep 3
echo ""
echo "── چک نهایی ──"
CODE=$(curl -s -o /dev/null -w "%{http_code}" http://localhost:3000/ || echo "000")
echo "   صفحهٔ اصلی: HTTP $CODE"
if [ "$CODE" = "200" ]; then
  echo ""
  echo "🎉 v221 با موفقیت دیپلوی شد!"
  echo "   حالا گام ۲: تست پیامک تیکت از داخل پنل."
else
  echo ""
  echo "⚠️ کد $CODE — چند ثانیه صبر کن و دوباره بزن: curl -s -o /dev/null -w \"%{http_code}\" http://localhost:3000/"
  echo "   اگر هنوز 200 نشد، خروجی «pm2 logs fitup --lines 30» را برای من بفرست."
fi
FITUP_DEPLOY_221
```

## گام ۲ — تست پیامک تیکت با شمارهٔ خودت (۱ دقیقه، داخل پنل)

1. وارد پنل ادمین شو → تب تنظیمات/ابزار → کارت **«ممیزی پیامک‌های سیستمی»**
2. در کادر «شمارهٔ تست»، شمارهٔ خودت را بزن
3. از لیست، سناریوی **«تیکت پشتیبانی (942763)»** را باز کن → دکمهٔ **«ارسال تست این سناریو»** را بزن
4. پیامک واقعی باید تا چند ثانیه به گوشی‌ات برسد ✅
5. اگر به هر دلیلی نرسید، **دلیل دقیق** همان‌جا زیر سناریو نوشته می‌شود (مثلاً قالب تأیید نشده، کلید تنظیم نیست و…) — یک اسکرین‌شات برای من بفرست.

از این به بعد هم هر پیامک تیکت (جدید/پاسخ) در همان کارت ثبت می‌شود: موفق، ناموفق با دلیل، زمان و شمارهٔ گیرنده.

## در v221 چه چیزهایی درست شد؟ (توضیح ساده)

### ۱) چرا پیامک تیکت به تو نمی‌رسید؟ — ریشه پیدا و درمان شد

سه مشکل پشت‌سرهم بود:

| مشکل | توضیح ساده | فیکس |
|---|---|---|
| شمارهٔ مدیر فقط از تنظیمات سرور خوانده می‌شد | اگر متغیر `ADMIN_MOBILE` روی سرور تنظیم نبود/جا افتاده بود، برنامه اصلاً نمی‌دانست پیامک را به کجا بفرستد — و بی‌صدا از آن می‌گذشت؛ نه در پنل sms.ir چیزی می‌آمد نه هیچ‌جا ردی بود | حالا اگر تنظیمات نباشد، برنامه خودش شمارهٔ مدیر را از **دیتابیس** (حساب مدیر) پیدا می‌کند |
| شکست‌ها کاملاً بی‌صدا بودند | هر شکستی (بدون کلید، بدون شماره، بدون نام) هیچ ردپایی جا نمی‌گذاشت — در پنل ممیزی هم دیده نمی‌شد | حالا **هر** شکست با دلیل صریح در کارت «ممیزی پیامک‌ها» ثبت می‌شود |
| پیامک پاسخ به کاربرانِ بی‌نام نمی‌رفت | کاربری که اسمش را ثبت نکرده بود، پیامک پاسخ پشتیبانی نمی‌گرفت | حالا برایش با «ورزشکار» ارسال می‌شود (همان الگوی قبلی خودت) |

نتیجه: تیکت جدید → پیامک برای تو می‌آید. پاسخ کاربر → پیامک برای تو می‌آید. پاسخ تو → پیامک برای کاربر می‌رود (همیشه).

### ۲) ممیزی ریشه‌ای همهٔ پیامک‌ها

همهٔ ۱۷ مسیر پیامک (ورود، تیکت، خرید، ارتقا، کیف پول، تمدید، دعوت، ترک درگاه و…) تک‌به‌تک بررسی شدند:
- مسیر تیکت: ۴ ریشه پیدا و رفع شد (بالای جدول)
- بقیهٔ مسیرها از قبل لاگ کامل و ضدتکرار درست دارند — حالا سناریوی تیکت هم به همان سطح رسید
- کارت «ممیزی پیامک‌ها» حالا سناریوی تیکت را هم نشان می‌دهد + دکمهٔ تستش هست
- تست کامل جریان واقعی (ورود با کد → تیکت → پاسخ مدیر → پیامک کاربر) در محیط آزمایشی اجرا و پاس شد

### ۳) کارت تخفیف شخصی فقط در لحظهٔ «برنامه‌ات آماده شد»

- کارت پیشنهاد پلن بالاتر با کد تخفیف شخصی از بخش **«اولین عکس پیشرفت»** حذف شد
- فقط در لحظهٔ **«برنامه‌ات آماده شد»** نمایش داده می‌شود (همان‌جا که بیشترین ارزش را دارد)
- برای دارندگان پلن استاندارد/پیشرفته/حرفه‌ای همان قبل هیچ‌وقت نشان داده نمی‌شود
