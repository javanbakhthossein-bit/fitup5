## گام ۱ — دیپلوی (کپی/پیست یک‌جا)

1. فایل `fitup-deploy-2026-10-08-v222.zip` را روی سرور آپلود کن (مثلاً به `/root`).
2. **کل بلاک زیر را یک‌جا کپی کن، در ترمینال سرور پیست کن و اینتر بزن:**

```bash
bash <<'FITUP_DEPLOY_222'
# ═══════════════════════════════════════════════════════════
#  فیتاپ v222 — دیپلوی (unzip + build اگر لازم + ری‌استارت)
#  مطمئن: پوشهٔ db و uploads دست‌نخورده می‌مانند
# ═══════════════════════════════════════════════════════════
set -e
APP_DIR="/var/www/fitup"
ZIP="/root/fitup-deploy-2026-10-08-v222.zip"

echo "── ۱) پشتیبان سریع از دیتابیس ──"
DBF=$(ls -t "$APP_DIR"/db/*.db 2>/dev/null | head -1 || true)
if [ -n "$DBF" ]; then
  cp "$DBF" "/root/fitup-db-backup-$(date +%Y%m%d-%H%M%S).db" && echo "   ✅ بکاپ دیتابیس در /root ذخیره شد"
fi

echo "── ۲) unzip زیپ v222 ──"
cd "$APP_DIR"
unzip -oq "$ZIP" -d /tmp/fitup-v222
# همه‌چیز جز db و uploads و .env و .next/cache از روی پوشهٔ استخراج‌شده کپی می‌شود
rsync -a --exclude 'db/' --exclude 'uploads/' --exclude '.env' --exclude '.next/cache/' /tmp/fitup-v222/ "$APP_DIR"/
rm -rf /tmp/fitup-v222
echo "   ✅ فایل‌های v222 جایگزین شدند"

echo "── ۳) نصب وابستگی (فقط اگر package.json عوض شده باشد) ──"
cd "$APP_DIR"
if command -v bun >/dev/null 2>&1; then
  bun install --frozen-lockfile >/dev/null 2>&1 || bun install >/dev/null 2>&1 || true
elif command -v npm >/dev/null 2>&1; then
  npm ci >/dev/null 2>&1 || npm install >/dev/null 2>&1 || true
fi

echo "── ۴) اگر زیپ شامل بیلد آماده است، skip؛ وگرنه build ──"
if [ ! -d "$APP_DIR/.next" ]; then
  echo "   .next پیدا نشد — build می‌گیرم..."
  if command -v bun >/dev/null 2>&1; then bun run build; else npm run build; fi
fi

echo "── ۵) ری‌استارت pm2 ──"
(runuser -u $(stat -c '%U' "$APP_DIR") -- pm2 restart fitup 2>/dev/null) || \
(su - $(stat -c '%U' "$APP_DIR") -c "pm2 restart fitup" 2>/dev/null) || \
pm2 restart fitup

sleep 3
echo ""
echo "── چک نهایی ──"
CODE=$(curl -s -o /dev/null -w "%{http_code}" http://localhost:3000/ || echo "000")
echo "   صفحهٔ اصلی: HTTP $CODE"
if [ "$CODE" = "200" ]; then
  echo ""
  echo "🎉 v222 با موفقیت دیپلوی شد!"
  echo "   حالا گام ۲: چهار چک ساده بعد از دیپلوی."
else
  echo ""
  echo "⚠️ کد $CODE — چند ثانیه صبر کن و دوباره بزن: curl -s -o /dev/null -w \"%{http_code}\" http://localhost:3000/"
  echo "   اگر هنوز 200 نشد، خروجی «pm2 logs fitup --lines 30» را برای من بفرست."
fi
FITUP_DEPLOY_222
```

## گام ۲ — چهار چک بعد از دیپلوی

1. **صفحهٔ ۴۰۴ جدید:** آدرس الکی باز کن (مثلاً `fittup.ir/test123`) → باید لوگوی فیتاپ + جملهٔ «متاسفانه این صفحه در دسترس نیست؛ نگران نباش، از همین جا مسیرت را ادامه بده.» + دکمهٔ «ادامه» ببینی.
2. **پنجرهٔ چت حالت باشگاه:** پنل → داشبورد → «حالت باشگاه» → دکمهٔ شناور «چت با فیتاپ» → باید به‌صورت **مدال (پنجرهٔ کوچک با گردی بالا، نه تمام‌صفحه)** و خیلی سریع باز شود؛ دکمهٔ back گوشی اول چت را می‌بندد، بعد دفعهٔ بعد دیالوگ «از حالت باشگاه خارج می‌شی؟» می‌آید.
3. **نسخهٔ جدید اپ اختصاصی:** کاربران اپ اختصاصی با باز کردن اپ، مودال «نسخهٔ جدید 1.17.6» را می‌بینند و آپدیت می‌شوند (خودکار). آپ بازار 1.15.7 را باید جداگانه در پنل کافه‌بازار آپلود کنی (فایل داخل همین زیپ: `fitup-bazaar-v1.15.7.apk`).
4. **پرداخت:** یک خرید آزمایشی (یا از پنل ادمین تب مالی) — پرداخت‌های ناموفق حالا دیگر به‌صورت «در انتظار» معلق نمی‌مانند.

## در v222 چه چیزهایی درست شد؟ (توضیح ساده)

### ۱) «اتصال برقرار نیست» برای همیشه حذف شد (هر دو اپ اندروید)

سناریوی تو: اپ چند ساعت در پس‌زمینه بود → باز کردی → صفحهٔ «اتصال برقرار نشد» با دکمهٔ تلاش مجدد.
ریشه: سوکت‌های اینترنتِ اپ بعد از خواب طولانی گوشی مرده بودند و اولین تلاش شکست می‌خورد و به‌جای خودکار-دوباره-اتصال، صفحهٔ خطا نشان داده می‌شد.

| قبلاً | حالا |
|---|---|
| صفحهٔ «اتصال برقرار نشد» + دکمهٔ تلاش مجدد | این صفحه **کلاً حذف شد** — دیگر وجود خارجی ندارد |
| کاربر باید خودش بزند | اپ خودش با استکِ جدا از WebView مسیر اینترنت را می‌سنجد (اول ۳ بار سریع، بعد هر ۴ ثانیه — بی‌نهایت) و به‌محض سالم بودن مسیر، همان صفحهٔ قبلی را خودش بارگذاری می‌کند |
| برگشت از پس‌زمینه = اولین کلیک شکست می‌خورد | موقع برگشت به اپ، سوکت‌های مرده یک‌جا پاک می‌شوند → اولین درخواست با اتصال تازه باز می‌شود |

فقط اگر اینترنت گوشی واقعا قطع باشد، یک نمای آرام «در حال اتصال به فیتاپ…» با لودر می‌بینی (هیچ خطا/هیچ دکمه‌ای نیست) و به‌محض وصل شدن اینترنت، همه‌چیز خودش ادامه پیدا می‌کند.

### ۲) پنجرهٔ «چت با فیتاپ» در حالت باشگاه — مدال واقعی و پرسرعت

- قبلاً تمام‌صفحه باز می‌شد و با انیمیشن سنگین (محوِ پس‌زمینه = عامل لگ موبایل) — دقیقاً چیزی که گزارش کردی.
- حالا: **باتم‌شیت** (پنجرهٔ مدال از پایین، ۸۸٪ ارتفاع، گردی بالا) — روی دسکتاپ هم کارت مرکزی کوچک.
- انیمیشن باز/بسته = فقط transform/opacity روی گرافیک (سریع‌ترین حالت ممکن) + حذف کامل محوِ پس‌زمینه.
- چت بعد از اولین باز شدن در حافظه می‌ماند → باز شدن‌های بعدی **آنی** است (بدون لود مجدد تاریخچه).

### ۳) رفتار دکمهٔ back در حالت باشگاه (دقیقاً طبق خواستهٔ قبلی تو — تست شد)

چت باز است → back = بستن چت و برگشت به تمرین. هیچ لایه‌ای باز نیست → back = دیالوگ «از حالت باشگاه خارج می‌شی؟» → تأیید = خروج. (این رفتار در محیط آزمایشی با شبیه‌سازی back واقعی گوشی تست و تأیید شد.)

### ۴) ممیزی ضدلگ کل پنل (وب + وب‌اپ داخل هر دو اپ)

تمام پنل کاربری لایه‌به‌لایه بررسی شد؛ ریشهٔ اصلی لگ روی موبایل «افکت شیشه‌ای backdrop-blur» بود که در هر فریم اسکرول GPU را درگیر می‌کرد. فیکس‌ها:
- افکت شیشه‌ای روی موبایل در کل پنل خاموش شد (ظاهر تقریباً فرقی ندارد؛ سرعت محسوس بهتر می‌شود) — شامل ~۸۰ کارت شیشه‌ای پنل ادمین
- مدال ثبت سریع غذا، بنر تحلیل بدن، مدال به‌روزرسانی قوانین، دیالوگ خروج جلسات تمرین، تایمر استراحت باشگاه، هدر حالت باشگاه، نوار فیلتر بانک حرکات/غذاها، اسکریم‌های چت، پلیر موزیک — همه بی‌blur و سبک شدند
- نوار «در حال تحلیل» با transform به‌جای layout و انیمیشن‌های بی‌نهایت اضافه حذف/محدود شد
- گیت‌های نهایی: کامپایل TypeScript صفر خطا، ESLint صفر خطا، رندر مرورگری بدون خطای کنسول

### ۵) دو بهبود ریز در منطق پرداخت (از ممیزی امروز)

- استعلام درگاه: تراکنش‌های FAILED/REVERSED زرین‌پال دیگر «پرداخت‌شده» تشخیص داده نمی‌شوند → دیگر ردیف «در انتظار» شبح نمی‌ماند
- کامنت گمراه‌کنندهٔ مسیر خطای تحویل اصلاح شد (رفتار خودش درست بود)

### ۶) صفحهٔ ۴۰۴ جدید

متن قبلی (شوخی‌های تمرینی + عدد ۴۰۴ + لینک‌های زیاد) کلاً حذف شد. حالا: **لوگوی خود فیتاپ + «متاسفانه این صفحه در دسترس نیست؛ نگران نباش، از همین جا مسیرت را ادامه بده.» + یک دکمهٔ «ادامه»**.
